# Gum

Gum — небольшой язык для Windows (и Linux X11) со скриптами `.gum`. Старые файлы `.sek` тоже работают — расширение по-прежнему распознаётся.

Запускатель языка: `sekc.exe` (название бинарника сохранено для совместимости).

Gum умеет:

- печатать в консоль и показывать окна сообщений;
- отправлять клавиши и текст в активное окно, кликать мышью, перемещать курсор;
- объявлять хоткеи в стиле AHK;
- работать с файлами, переменными, циклами и условиями;
- делать HTTP-запросы и разбирать JSON;
- **управлять Telegram-ботом** без единого HTTP-вызова в коде — через встроенные команды `tg_*`.

## Файлы

- `build.bat` — сборка `sekc.exe` на Windows
- `build.sh` — сборка на Linux
- `run.bat file.gum` — сборка (при необходимости) и запуск скрипта на Windows
- `run.sh file.gum` — то же на Linux
- `sekc.exe file.gum` — прямой запуск скрипта
- `examples/` — примеры всех основных команд и конструкций языка
- `vscode-gum/` — локальное расширение VS Code (подсветка, snippets, запуск)

## Сборка

Windows:

```bat
build.bat
```

Для HTTP-функций на Windows нужна libcurl: установи MinGW с libcurl (например WinLibs) или положи рядом заголовки `curl/` и библиотеку (`libcurl.a`), чтобы заработал флаг `-lcurl` в `build.bat`. Рядом с собранным `sekc.exe` должен лежать `curl-ca-bundle.crt` для проверки HTTPS-сертификатов (он уже есть в проекте). Без него HTTPS-запросы (в том числе все запросы к Telegram) будут падать с ошибкой сертификата.

## Запуск

```bat
run.bat hello.gum
```

Если в скрипте есть хоткеи, процесс останется запущенным и будет ждать нажатий. Если в скрипте установлен токен бота (`tg_token`), процесс перейдёт в режим long polling и будет ждать сообщения от Telegram. Остановка — `Ctrl+C`.

## Linux

Язык собирается и работает и на Linux (X11). Исходники те же, платформенный слой выбирается компилятором.

Зависимости:

```bash
# Debian / Ubuntu
sudo apt install g++ libx11-dev libxtst-dev libcurl4-openssl-dev

# Fedora
sudo dnf install gcc-c++ libX11-devel libXtst-devel libcurl-devel

# Arch
sudo pacman -S gcc libx11 libxtst libcurl
```

Сборка и запуск:

```bash
chmod +x build.sh run.sh        # можно и просто: bash build.sh
./build.sh                      # соберёт ./sekc
./run.sh mainpik.gum            # соберёт при необходимости и запустит
./sekc file.gum                 # прямой запуск
```

Особенности:

- Хоткеи, `click`, `mousemove`, `send` работают только в сессии X11 (не в Wayland напрямую) и требуют запущенного дисплея (`DISPLAY`).
- `msg` показывает окно через `zenity` или `xmessage` (поставь любой из них).
- `playsound` воспроизводит файл через `aplay` (ALSA) или `paplay` (PulseAudio).
- `send` печатает текст через XTest: обычные ASCII-символы на активной раскладке. Символы, которых нет в текущей раскладке, пропускаются.
- Остановка — `Ctrl+C` или закрытие терминала.

## VS Code расширение

В папке `vscode-gum/` лежит локальное расширение для `.gum` и `.sek`: подсветка, snippets, быстрый запуск через `sekc.exe`, вывод в реальном времени и запуск в терминале. Расширение подсказывает и все Telegram-команды `tg_*`.

Установка:

```powershell
powershell -ExecutionPolicy Bypass -File .\vscode-gum\install.ps1
```

После перезагрузки VS Code открой `.gum` файл и нажми `Ctrl+F5` или кнопку `Gum Run` в статусбаре. Для интерактивных скриптов есть команда `Gum: Run Script in Terminal`, а для автоперезапуска после изменений — `Gum: Toggle Live Run`.

## Синтаксис

- Обычно одна команда на строку
- `;` тоже можно использовать как разделитель
- Строки пишутся в двойных кавычках
- В строках есть escape-последовательности: `\\`, `\"`, `\n`, `\t`, `\r`
- Комментарии начинаются с `#`

```text
# это комментарий
print "hello"; print "world"   # ; разделяет команды в одной строке
```

## Типы

- `number` — целые и дробные числа
- `string` — строка в двойных кавычках
- `boolean` — `true` / `false`
- `nil` — значение без результата
- `json` — хэндл на распарсенный JSON (возвращается из `json_parse` и `json_get`)

Проверить тип можно функцией `type(...)`.

## Операторы

- `+` `-` `*` `/` — арифметика (для строк `+` — склейка)
- `==` `!=` — сравнение
- `>` `>=` `<` `<=` — сравнение чисел
- `!` — логическое отрицание (унарный)
- `-` — унарный минус
- `and` — логическое И (оба операнда истинны)
- `or` — логическое ИЛИ (хотя бы один истинен)

`and` и `or` работают по законам булевой логики и всегда возвращают `true` или `false`. Приоритет: `or` самый низкий, `and` выше него, потом сравнения и арифметика. Вычисление ленивое: если результат уже понятен, вторая часть выражения не выполняется (это безопасно и с `random(...)`).

```text
let age = 25
if age >= 18 and age < 65
    print "взрослый, рабочий возраст"
end

if age < 10 or age > 80
    print "крайний возраст"
end

print true and false    # false
print true or false     # true
print !false            # true
```

## Переменные

Создание переменной:

```text
let x = 10
```

Изменение переменной (простое присваивание):

```text
x = x + 1
```

Явное изменение через `set`:

```text
set x = 2
```

Правила:

- `let` создаёт новую переменную
- `set name = ...` и `name = ...` меняют уже созданную переменную; если её нет — ошибка `Undefined variable`
- переменные видны во всём скрипте, включая группы и хоткеи

### `save` / `load`

`save` записывает все текущие переменные в файл, `load` загружает их обратно.

```text
let player_name = "root"
let level = 1

save "save.gum"
set player_name = "changed"
set level = 99

load "save.gum"

print player_name   # root
print level         # 1
```

Файл сохранения хранит значения типов `number`, `string`, `boolean` и `nil`. При загрузке переменные из файла создаются или заменяют уже существующие.

## Команды

### `print`

Вывод в консоль.

```text
print "hello"
print 10 + 5
print "score: " + score
```

### `msg`

Показывает обычное окно сообщения Windows, как `MsgBox` в AHK (на Linux — через `zenity`/`xmessage`).

```text
msg "hello"
msg "random: " + random(100)
```

### `send`

Отправляет текст в активное окно через Windows `SendInput` (на Linux — через XTest).

Правила:

- `send` ждёт строковое выражение
- окно должно быть уже в фокусе
- специальные клавиши пишутся через `{Key}`
- несколько кусков текста и клавиш склеиваются без пробелов

```text
send "hello"
send "piska"{Enter}
send {Space}
send "line 1"{Enter}"line 2"
```

Поддерживаемые специальные клавиши:

- `{Enter}`
- `{Tab}`
- `{Space}`
- `{Esc}`
- `{Up}` `{Down}` `{Left}` `{Right}`
- `{Delete}` `{Backspace}`
- `{Home}` `{End}`
- `{PgUp}` `{PgDn}`
- `{F1}` ... `{F12}`
- одиночные буквы и цифры, например `{A}` или `{7}`

### `click`

Делает левый клик мышью в текущей позиции курсора.

Правила:

- `click` не принимает аргументы
- курсор должен быть уже наведён в нужное место

```text
click
sleep 500
click
```

### `mousemove`

Перемещает курсор мыши в указанные экранные координаты (пиксели).

```text
mousemove, <x>, <y>
```

`<x>` и `<y>` — числовые выражения (можно использовать переменные или `random(...)`).

```text
mousemove, 100, 200
mousemove, random(0, 1920), random(0, 1080)
```

### `playsound`

Запускает звуковой файл из скрипта.

```text
playsound "beep.wav"
```

### `sleep`

Пауза в миллисекундах.

```text
sleep 1
sleep 15
sleep 33.5
```

### `toggle`

Переключает булевую переменную:

- `true` -> `false`
- `false` -> `true`

```text
let enabled = true
toggle enabled
print enabled   # false
```

Если переменная не булева, команда выдаст ошибку.

### `loop`

Повторяет блок несколько раз или бесконечно.

```text
loop 5
print "hello"
end
```

```text
loop
click
sleep 10
end
```

Именованный цикл, который можно остановить изнутри:

```text
loop {3}
click
if random(100) > 95
    unloop {3}
end
end
```

Правила:

- `loop` может работать с числом или без него
- `loop {3}` задаёт номер цикла, чтобы потом остановить именно его
- если число дробное, берётся целая часть вниз
- отрицательное число запрещено
- если числа нет, блок повторяется бесконечно, пока ты не остановишь скрипт
- блок закрывается словом `end`

### `unloop`

Останавливает именованный `loop` по его номеру.

```text
unloop {3}
```

Правила:

- работает только с циклом, у которого есть номер, например `loop {3}`
- номер цикла должен быть положительным целым числом
- остановка происходит, когда код доходит до `unloop {3}` или когда цикл с таким номером в следующий раз проверяет флаг остановки

### `if` / `elif` / `else`

Условные блоки.

```text
if random(10) > 5
    print "big"
elif random(10) > 2
    print "mid"
else
    print "small"
end
```

Правила:

- `if` принимает выражение-условие (слово `then` писать не нужно)
- `elif` проверяется, если предыдущие ветки не сработали
- `else` выполняется, если ни одно условие не подошло
- блок закрывается словом `end`

### `use`

Подключает другой файл как библиотеку. Путь считается относительно файла, где написан `use`.

```text
use "lib.gum"

print app_name
```

Если подключённый файл сам использует `use`, такие подключения тоже разворачиваются. Циклическое подключение остановится с ошибкой.

### `group`

Создаёт группу команд. Группа не выполняется сама по себе — её нужно вызвать по имени через `()`.

```text
group install_tools
    print "installing terminal"
    print "installing editor"
end

install_tools()
```

В этой версии `group` без параметров и без `return`. Группа видит обычные переменные скрипта.

## Хоткеи

Хоткеи в стиле AHK:

```text
x::
print "pressed x"
sleep 5
send "hello"
```

Поддерживается и короткая однострочная форма:

```text
f: toggle enabled
```

Правила:

- `x::` значит, что блок ниже выполнится при нажатии `x`
- `f: команда` значит, что одна команда выполнится по нажатию `f`
- блок хоткея продолжается до следующего хоткея или конца файла
- обычный код верхнего уровня выполняется один раз при старте
- хоткеи регистрируются до запуска верхнего уровня, поэтому они могут срабатывать даже пока стартовый `loop` ещё крутится
- переменные сохраняются между срабатываниями
- хоткеи работают и в режиме Telegram-поллинга: нажатия обрабатываются между проверками обновлений

Поддерживаются одиночные триггеры:

- `a-z`
- `0-9`
- `F1-F12`
- `Enter`, `Tab`, `Space`, `Esc`
- стрелки
- `Delete`, `Backspace`, `Home`, `End`, `PgUp`, `PgDn`

## Встроенные функции

### `input(...)`

Считывает строку из консоли.

```text
let name = input("Your name: ")
print name
```

### `random(...)` / `rand(...)`

Генератор случайных чисел.

Варианты:

- `random()` — дробное число от `0.0` до почти `1.0`
- `random(100)` — целое число от `0` до `100`
- `random(5, 20)` — целое число от `5` до `20`
- `rand(...)` — алиас

```text
print random()
print random(10)
print random(1, 100)

let x = rand(5, 9)
print x
```

### `seed(...)`

Управляет seed генератора случайных чисел.

```text
seed()
print random(100)

seed(123)
print random(100)
```

### `type(...)`

Возвращает тип значения строкой: `number`, `string`, `boolean`, `nil` или `json`.

```text
let x = 123
print type(x)       # number
```

### `assert(...)`

Проверяет условие и останавливает скрипт с понятной ошибкой, если условие ложное.

```text
let enabled = true
assert(enabled == true, "enabled must be true")
```

### `http_get(url)` / `http_post(url, body, content_type)`

Выполняют HTTP-запросы через libcurl. Полезно для работы с REST API.

- `http_get(url)` — GET-запрос, возвращает тело ответа строкой.
- `http_post(url, body, content_type)` — POST-запрос. `content_type` задаёт заголовок `Content-Type` (например `"application/json"`). Если аргумент не указан, используется `"text/plain"`.

Правила:

- таймаут запроса — 30 секунд
- `User-Agent` — `gum/1.0`
- при ошибке (нет сети, таймаут, HTTP-статус 4xx/5xx) возвращается пустая строка `""`, скрипт не останавливается
- для HTTPS используется CA-файл `curl-ca-bundle.crt`, лежащий рядом с `sekc.exe`

```text
let url = "https://api.telegram.org/bot<TOKEN>/getMe"
let response = http_get(url)
print response
```

### `json_parse(str)` / `json_get(obj, key)`

Парсинг JSON и чтение значений.

- `json_parse(str)` — разбирает строку JSON и возвращает объект типа `json` (хэндл на внутреннее представление). При ошибке парсинга возвращает `nil`.
- `json_get(obj, key)` — возвращает значение по ключу: число, строку, boolean, `nil` или другой объект `json` (для вложенных объектов и массивов). Если ключа нет — `nil`.

```text
let response = http_get("https://httpbin.org/get")
let obj = json_parse(response)
let url = json_get(obj, "url")
print url
```

### `json_array_length(arr)` / `json_array_get(arr, index)`

Работа с JSON-массивами.

- `json_array_length(arr)` — длина массива (число). Если передан не массив — `nil`.
- `json_array_get(arr, index)` — элемент по индексу (с нуля). Если индекс вне диапазона — `nil`.

```text
let tags = json_get(obj, "tags")
print json_array_length(tags)
print json_array_get(tags, 0)
```

### `json_type(val)`

Возвращает тип значения строкой. Для объектов `json` — JSON-тип: `"number"`, `"string"`, `"boolean"`, `"null"`, `"object"`, `"array"`. Для обычных значений Gum: `"nil"` → `"null"` и т.д. Удобно для отладки.

```text
print json_type(json_parse("{\"a\":1}"))   # object
print json_type(json_get(obj, "name"))     # string
```

### `os_*` файловые функции

Мини-набор как `os` в Python: можно создавать файлы и папки, читать, перезаписывать, дописывать, копировать, переименовывать и удалять.

- `os_exists(path)` / `os_isfile(path)` / `os_isdir(path)` — проверить путь
- `os_touch(path)` / `os_write(path, text)` / `os_append(path, text)` / `os_read(path)` — создать, записать, дописать и прочитать файл
- `os_remove(path)` / `os_mkdir(path)` / `os_rmdir(path)` — удалить файл, создать папку, удалить пустую папку
- `os_rename(from, to)` / `os_copy(from, to)` — переименовать/переместить или скопировать файл

```text
os_mkdir("data")
os_write("data/note.txt", "hello")
os_append("data/note.txt", " world")

print os_read("data/note.txt")
print os_exists("data/note.txt")

os_copy("data/note.txt", "data/copy.txt")
os_rename("data/copy.txt", "data/renamed.txt")
os_remove("data/note.txt")
os_remove("data/renamed.txt")
os_rmdir("data")
```

Полный пример: `examples/20_files.sek`.

# Telegram-боты

Встроенная поддержка Telegram Bot API. Достаточно установить токен, определить пару групп-обработчиков — и Gum сам займётся HTTP-запросами, JSON и long polling. Никакого `http_get`/`http_post`/`json_parse` писать не нужно.

## Как включить

1. Создай бота у [@BotFather](https://t.me/BotFather) и получи токен вида `123456789:AAE...`.
2. Напиши `tg_token "<токен>"` в начале скрипта.
3. Определи обработчики `on_tg_message` и/или `on_tg_callback` (группы `group`).
4. Запусти скрипт. Gum выполнит верхнеуровневые инструкции, напечатает

   ```
   Listening for Telegram updates. Press Ctrl+C to stop.
   ```

   и уйдёт в цикл опроса обновлений. Остановка — `Ctrl+C`.

## Команды Telegram

Все команды пишутся словом, аргументы — через пробел. Строковые аргументы — в двойных кавычках, числа — как есть.

### `tg_token <token>`

Устанавливает токен бота.

```text
tg_token "123456789:AAH...токен..."
```

- Токен передаётся строкой в кавычках.
- При первом использовании токен проверяется через метод `getMe` (GET-запрос к API).
- Если токен невалиден или бот недоступен, в консоль печатается `[gum] tg_token: invalid token or bot unavailable (...)` и скрипт останавливается с ошибкой `gum error: Invalid Telegram bot token (getMe failed)` (код выхода 1).
- Без валидного токена Telegram-команды работать не будут.

### `tg_on <command> <reply>`

Регистрирует статичный ответ на команду — без написания обработчика.

```text
tg_on "/start" "Привет, я бот!"
tg_on "/help" "Напиши мне что-нибудь, и я повторю."
```

- `<command>` и `<reply>` — строки в двойных кавычках.
- Когда приходит сообщение с текстом, в точности равным `<command>`, бот автоматически отправляет `<reply>` в тот же чат.
- Поддерживается несколько `tg_on`; порядок регистрации не важен.
- Можно комбинировать с группой `on_tg_message`: сначала срабатывает статичный ответ, потом вызывается группа.

### `tg_send <text>` или `tg_send <chat_id> <text>`

Отправляет текст.

```text
tg_send "Привет!"
tg_send 123456789 "Привет в другой чат!"
```

- С одним аргументом текст уходит в последний известный чат (тот, откуда пришло последнее сообщение, или сохранённый в `TG_CHAT_ID`).
- С двумя аргументами первый — числовой id чата, второй — текст.
- Если последнего чата нет (например, бот стартовал и сразу вызвал `tg_send`), печатается `[gum] tg_send: no chat to send to`, скрипт продолжает работу.

### `tg_reply <text>`

Отправляет текст как ответ на последнее полученное сообщение (автоматически подставляет `reply_to_message_id`). Использует `TG_CHAT_ID` и `TG_MESSAGE_ID`.

```text
tg_reply "Я ответил на твоё сообщение"
```

Если нет входящего сообщения — печатается `[gum] tg_reply: no incoming message to reply to`.

### `tg_typing`

Показывает индикатор «печатает...» в текущем чате (метод `sendChatAction` с `action="typing"`). Ставь перед длительными операциями.

```text
tg_typing
sleep 3000
tg_send "Готово!"
```

### `tg_photo <file>` или `tg_photo <chat_id> <file>`

Отправляет фото. `<file>` — `file_id` (строка) или URL (строка).

```text
tg_photo "AgACAgIAAxkBAA..."                       # в последний чат по file_id
tg_photo 123456789 "https://example.com/cat.jpg"   # в конкретный чат по URL
```

### `tg_sticker <file>` или `tg_sticker <chat_id> <file>`

Отправляет стикер — аналогично `tg_photo`.

```text
tg_sticker "CAACAgIAAxkBAA..."
```

### `tg_delete` / `tg_delete <chat_id>` / `tg_delete <chat_id> <message_id>`

Удаляет сообщение.

- Без аргументов — удаляет последнее отправленное ботом сообщение в текущем чате.
- С одним аргументом — `<chat_id>` + последнее сообщение бота.
- С двумя — `<chat_id>` и `<message_id>` (полностью явно).
- Если бот ещё ничего не отправлял — `[gum] tg_delete: no bot message to delete`.

### `tg_edit <new_text>`

Редактирует последнее отправленное ботом сообщение (метод `editMessageText`).

```text
tg_edit "Новый текст"
```

- Если сообщение связано с callback (пришёл `callback_query`), правится именно оно — удобно для динамических меню.
- Если бот ещё ничего не отправлял — `[gum] tg_edit: no bot message to edit`.

### `tg_callback_answer <text>`

Отвечает на callback-запрос кнопки (метод `answerCallbackQuery`). Убирает «часики» на кнопке и показывает уведомление.

```text
tg_callback_answer "Готово"
```

Используется внутри `on_tg_callback`. Без callback — `[gum] tg_callback_answer: no callback to answer`.

### `tg_get_chat <chat_id>`

Получает информацию о чате и печатает её в консоль:

```
[gum] chat 123456789 (private): Иван
```

Формат: `[gum] chat <id> (<type>): <name>`, где `<type>` — `private`, `group`, `supergroup` или `channel`, `<name>` — `first_name`/`title`.

### `tg_leave <chat_id>`

Заставляет бота покинуть чат/группу.

```text
tg_leave -1001234567890
```

### `tg_cmd_hash(<string>)`

Встроенная функция (вызывается через `()`), возвращает числовой хеш строки по алгоритму FNV-1a 32-bit.

```text
print tg_cmd_hash("/start")     # какое-то число, например 1147651859
```

Предназначена для сравнения с `TG_TEXT` и `TG_CALLBACK_DATA`.

## Глобальные переменные `TG_*`

При каждом обновлении Gum заполняет глобальные переменные (до первого обновления они равны `nil`):

| Переменная          | Тип        | Описание                                                        |
|---------------------|------------|-----------------------------------------------------------------|
| `TG_CHAT_ID`        | number     | ID чата, откуда пришло обновление                              |
| `TG_MESSAGE_ID`     | number     | ID сообщения (для сообщений и callback-сообщений)              |
| `TG_TEXT`           | number     | **Хеш** текста сообщения (FNV-1a 32-bit)                        |
| `TG_CALLBACK_DATA`  | number     | **Хеш** данных нажатой кнопки (`callback_data`)                |
| `TG_CALLBACK_ID`    | string     | ID callback-запроса (для ответа через `tg_callback_answer`)     |

### Почему хеши, а не строки?

В Gum нет типа «строка внутри условия как значение» в таком виде, который позволил бы безопасно сравнивать строки в `TG_TEXT`. Чтобы не плодить сложные механизмы, текст сообщения и данные кнопки приходят в виде **числовых хешей** (FNV-1a 32-bit). Для сравнения с конкретной командой используй функцию `tg_cmd_hash("...")`:

```text
if TG_TEXT == tg_cmd_hash("/start")
    tg_send "Привет!"
end
```

Это читается как «если текст сообщения равен "/start"», и работает быстро и детерминированно: `tg_cmd_hash("...")` всегда возвращает одно и то же число для одной строки.

## Обработчики

Определи группы с фиксированными именами — они опциональны, но без них бот ничего не будет делать с сообщениями (кроме статичных `tg_on`).

### `group on_tg_message`

Вызывается на каждое текстовое сообщение. Доступны `TG_CHAT_ID`, `TG_TEXT`, `TG_MESSAGE_ID`.

```text
group on_tg_message
    if TG_TEXT == tg_cmd_hash("/start")
        tg_send "Привет!"
    elif TG_TEXT == tg_cmd_hash("/time")
        tg_send "Точное время не поддерживается, но привет!"
    else
        tg_reply "Я тебя не понял. Напиши /start"
    end
end
```

### `group on_tg_callback`

Вызывается на нажатие кнопки (callback-запрос). Доступны `TG_CHAT_ID`, `TG_CALLBACK_DATA`, `TG_CALLBACK_ID`. Сообщение кнопки становится целью для `tg_edit`/`tg_delete`.

```text
group on_tg_callback
    tg_callback_answer "Готово"
    if TG_CALLBACK_DATA == tg_cmd_hash("button1")
        tg_edit "Вы нажали кнопку 1"
    elif TG_CALLBACK_DATA == tg_cmd_hash("button2")
        tg_edit "Вы нажали кнопку 2"
    end
end
```

## Автоматический long polling

- Запускается автоматически после выполнения всех верхнеуровневых инструкций, если установлен токен (`tg_token`).
- Используется `getUpdates` с параметрами `offset` (сохраняется между вызовами), `timeout=30`, `allowed_updates=["message", "callback_query"]`.
- `update_id` каждого обновления запоминается, и `offset = update_id + 1` — повторных обработок нет.
- Между раундами опроса пауза 500 мс (задана в API-спецификации).
- Пока бот слушает, между обновлениями обрабатываются горячие клавиши (если они есть в скрипте).
- Остановка — `Ctrl+C`.

## Обработка ошибок и конфликтов

Все ошибки печатаются в консоль, скрипт по возможности продолжает работу:

- **409 Conflict** — другой экземпляр этого же бота уже опрашивает API. Gum печатает предупреждение и завершает работу: два процесса с одним ботом одновременно невозможны.
- **429 Too Many Requests** — лимит запросов. Gum ждёт время из `Retry-After` (или 500 мс) и повторяет опрос.
- **HTTP 5xx / сетевые ошибки** — повтор опроса через 500 мс.
- **Невалидный токен** — единственный случай, когда скрипт останавливается сразу (см. `tg_token`).

## Технические детали

- Все методы вызываются через `POST` с JSON-телом на `https://api.telegram.org/bot<TOKEN>/<METHOD>`.
- Таймаут запросов — 30 секунд, `User-Agent` — `gum/1.0`.
- Для HTTPS нужен `curl-ca-bundle.crt` рядом с `sekc.exe` (уже есть в проекте).
- Ошибки не останавливают скрипт (кроме невалидного токена): неверное число аргументов, отсутствие чата/сообщения печатаются в stderr в формате `[gum] <команда>: <описание>`.

## Готовый бот-пример

Минимальный эхо-бот со статичными ответами:

```text
tg_token "123456789:AAH...токен..."

tg_on "/start" "Привет, я бот!"
tg_on "/help"  "Напиши мне что-нибудь, и я повторю."

group on_tg_message
    if TG_TEXT == tg_cmd_hash("/start") or TG_TEXT == tg_cmd_hash("/help")
        tg_send "Пиши мне что угодно — я эхо!"
    else
        tg_typing
        tg_reply "Эхо: " + tg_text_to_string(TG_TEXT)
    end
end
```

> Примечание: `tg_text_to_string` не существует — в этой версии Gum текст доступен только в виде хеша. Чтобы отправить текст, отправляй фиксированные строки или конструируй их из известных частей.

Полный рабочий пример с заменяемым токеном: [examples/25_telegram.gum](examples/25_telegram.gum).
